## What the rig established

- **Baseline decode on this machine: ~20.5 tok/s, verify_ms median 48.7 ms**
  for an 8B 4-bit target. Python overhead per window is ~0.07 ms (window_ms
  minus verify_ms) — a Rust extension would buy nothing, as the brief said.
- **The laziness trap is real and quantified:** an un-evaluated 1B decode
  step times at 0.32 ms; evaluated, 13.0 ms — 40× apart
  (`tests/test_laziness.py`). Every MLXBackend method forces `mx.eval`.
- **An idle desktop is not idle.** 102 and 103 of 2143 windows (4.8%) had
  page-ins during the window in both runs, with zero memory-pressure and
  zero thermal rows. These are background file reads (Spotlight, media
  analysis) landing in the 1 Hz guard tick a window straddles. They are
  excluded, not hidden — `page_ins` is in every row.
- **Repeatability is excellent for a plain baseline** (0.14%). This is the
  noise floor speculative-vs-baseline differences must clear.

## Guard design decisions on record

- `page_ins` = `psutil.swap_memory().sin // page_size`, verified equal to
  `vm_stat` Pageins on this machine — no shell-out on the sampling thread.
- `mem_pressure` from `sysctl kern.memorystatus_vm_pressure_level` (1/2/4 →
  0/1/2). `thermal_level` from `pmset -g therm` (0 when nominal; no key
  is printed at all when nothing is throttled).
- Startup fit guard budgets total memory minus a 4.5 GB OS reserve rather
  than psutil "available", because macOS holds recently read weight files
  as active page cache that MLX then maps again. The brief's 14B+1B
  configuration (1.4 GB headroom) is refused by construction.
