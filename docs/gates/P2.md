# P2 gate — losslessness harness

**Gate:** 20 prompts at temperature 0: speculative output token-identical to
plain decoding, 20/20.

**Result: FAIL, twice, identically — 19/20 on both attempts.** Stopped for
the owner's decision per the phase rules. The gate was not loosened.

## The runs (2026-09-16, M4 Mac mini 16 GB, mlx 0.32.2, mlx-lm 0.31.3)

`uv run acceptrate verify lossless --prompts 20 --k 4 --max-tokens 128`,
8B 4-bit target + 1B 4-bit draft, chat template, 20 train-split prompts
round-robin over the six tags.

Attempt 1 and attempt 2 produced byte-identical output (generation is
deterministic on this machine). 19 prompts token-identical. The one
divergence:

```
DIFF summarize-006  tokens=128 windows= 31 alpha=0.76  at 19: plain 11 vs spec 574, sequential top-2 margin 0.0000
```

Token 11 is `,` and token 574 is ` was`, after the context
`* **Cause:** A nightly analytics job`. Both have logit **20.578125** in the
sequential path — an exact fp16 tie. (fp16 spacing at magnitude 20 is
0.0156.) `np.argmax` breaks the tie toward the lower index (11); in the
batched verify pass the same position came out with 574 strictly ahead.

## Root cause: two Metal kernel paths, one fp16 model

Batched verification (N = K+1 tokens per forward) and sequential decoding
(N = 1) run different attention/matmul kernels. Measured on the 8B target
over 400 positions across 10 prompts, comparing the logits row for the same
position on both paths:

| logits | argmax flips | max\|Δ\| p50 | p99 | max |
|---|---|---|---|---|
| fp16 head (stock) | 0 / 400 | 0.031 | 0.075 | 0.102 |
| fp32 head from the same fp16 hidden state | 1 / 400 (a ≤1-ulp tie) | 0.030 | 0.073 | 0.099 |

The disagreement is ~0.03 typical, 0.10 worst case — hidden-state noise,
not output rounding, which is why computing the output head in float32 does
nothing (and costs +2.4% per step, 49.1 → 50.3 ms).

Sequential-path tie statistics over 320 positions: 1 exact tie, 3 within
one fp16 ulp. So a 20 × 128-token gate run contains several positions where
the two paths are free to disagree; empirically one of them flipped.

This is not a bug in the speculative logic: the logic is proven lossless
against plain greedy by a hypothesis property over arbitrary draft rules
(`tests/test_speculative.py`), the 1B model drafting for itself is
token-identical on real weights, and our plain greedy is token-identical to
mlx-lm's own greedy on 9/9 prompts (`docs/reference/mlx_lm_speculative.md`).
mlx-lm's own draft-model path has the same exposure by construction.

## Consequence

On MLX/Metal with fp16 4-bit models, "the token plain decoding would
produce" is undefined at positions where the target's top-2 logit margin is
below the cross-kernel noise floor (~0.1). Exact 20/20 greedy equivalence
is therefore a probabilistic outcome for *any* speculative implementation
on this platform, not a property an implementation can guarantee. Rate
observed here: 1 divergence in 2,479 generated tokens.

## Options for the owner (none taken yet)

1. **Re-specify the gate with a measured threshold** (recommended): a
   divergence counts as a failure unless the sequential top-2 margin at
   that index is below the noise floor measured on this hardware (0.10,
   reproducible by a committed calibration command); the harness must print
   every such near-tie. Losslessness is then "exact up to kernel noise",
   which is the strongest claim the platform admits — and the finding goes
   in the report.
2. **Force both paths through the same kernel shape** (pad plain decoding
   to N = K+1 per step). Bitwise identical, but it changes the baseline's
   cost profile and would no longer be "plain decoding".
3. **Accept 19/20 as a documented, deterministic, fully-explained
   exception** and proceed; the gate stays literally failed on record.
