# P6 gate — cold-start predictor and TUI

**Gate:** predictor beats a constant prior on held-out prompts; TUI renders
at ≥ 30 fps while generating.

**Result: PASS** (2026-09-16)

## Predictor

`HistGradientBoostingRegressor` over 13 prompt-text features (length,
lines, code fences, brace/bracket/digit/punctuation ratios, character
entropy, code keywords, …), target = per-token acceptance of the prompt
pooled over every K ≥ 1 window of the sweep. Trained on the 36 train-split
prompts; evaluated on the held-out prompts' acceptance from the P5 traces.

```
$ uv run acceptrate predictor train --traces traces/sweep --out calibration/predictor.joblib
trained on 36 prompts (alpha mean 0.824) -> calibration/predictor.joblib
$ uv run acceptrate predictor eval --train-traces traces/sweep --heldout-traces traces/p5
held-out prompts=35  predictor MAE 0.0625  constant-prior MAE 0.0772  improvement +19.1%
P6 predictor gate: PASS
```

Honest framing: 36 training rows is small, and the improvement is on the
opening α only; the runtime's EWMA takes over after a few windows.

## Machine profile (`acceptrate calibrate`, ~2 min)

Written to `~/.acceptrate/profile.json`; `serve --adaptive` reads it.

```
baseline 22.74 tok/s  alpha prior 0.83
c by K: K1=0.190/v1.00, K2=0.181/v1.05, K4=0.119/v1.58, K8=0.062/v3.00
```

The verify-cost curve v(K) measured here from six prompts matches the
full sweep's (1.00 / 1.05 / 1.57 / 2.96) — the P4 finding replicates from a
two-minute profile.

## Distributional losslessness (T > 0)

```
$ uv run acceptrate verify distributional --prompt-id prose-001 --k 4 --temperature 1.0 --n-samples 400
prose-001 K=4 T=1.0: TV 0.1825 vs bound 0.5254 (n=400/400)
distributional check: PASS
```

Rejection-sampling speculative decoding vs plain sampling, 400 draws each
of token index 1. The two-sample Bretagnolle–Huber–Carol bound is loose at
this n (0.53 with the observed support); the fakes-based negative control
in `tests/test_distributional_fakes.py` shows an always-accept draft fails
it at 2× the bound. A tighter test (chi-square) is future work.

## TUI

Go + Bubble Tea v2 client, a separate process talking HTTP to `acceptrate
serve`. Frame budget measured on the model+view path with a synthetic busy
state at 120×40:

```
$ cd tui && go run ./cmd/acceptrate-tui --benchmark-frames 300
300 frames in 165ms: 1816 fps (model+view, 120x40)
```

Bubble Tea's cell-diff renderer sits on top and is capped at `--fps` (30
by default); the Go test suite asserts the ≥ 30 fps gate with margin.
Demo without a model: `make chat-demo` (in-process mock replaying α rising
0.45 → 0.80 and K stepping 4 → 6).
